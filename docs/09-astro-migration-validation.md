# Astro + React 전환 검증

- 검증일: 2026-11-03
- 작업 브랜치: `codex/astro-react-migration`
- 원본 커밋: `7707044fb5e352e54abf4b314116b32f54eb009f`
- 환경: Windows, Node 24.14.1, npm 11.11.0, Astro 7.4.5, React 19.3.1

## 보존 범위

40개 페이지(홈 1, TIL 목록 1, TIL 글 37, 프로젝트 1)를 동일한 `.html` 경로에 생성한다. 본문은 `src/content/pages/`로 추출했으며 글과 코드를 다시 작성하지 않았다. 기존 CSS, 테마·코드 강조 스크립트, 사진과 다운로드 파일은 내용 변경 없이 `public/`로 이동했다.

기존 giscus 스크립트가 있는 35개 페이지는 모든 임베드 설정을 보존했다. 댓글이 없던 두 글에는 새 댓글 UI를 추가하지 않았다.

- `npm ci`: lockfile 재설치 성공. npm audit 취약점 0개.
- `npm run check`: 오류·경고·힌트 0개.
- `npm run build`: 40개 정적 HTML 생성.
- `npm run verify`: 749개 내부 링크·자산 참조·앵커, 현재 원문과 생성 본문 일치, 페이지별 메타 설명·h1·언어, React 적용 범위 검사 통과.
- `npm run verify:migration`: 40개 기존 URL의 본문 구조·텍스트·코드·메타데이터·헤더·푸터·댓글 설정 및 공개 자산 6개의 원본 대조 통과.
- `git diff --check`: 공백 오류 없음.
- `lint` 명령은 별도 구성하지 않았다.

## 브라우저 검사

SPA fallback이 없는 로컬 정적 HTTP 서버에서 빌드 결과를 확인했다.

- 홈·목록·프로젝트·대표 글: 직접 `.html` 접속, 대표 글 새로고침 정상.
- 필터: 전체 37개, 게임 엔진 9개, 운영체제 2개, 메모리 관리 1개, 프로그래머스 문제 풀이 10개, 알고리즘과 자료구조 9개, 컴퓨터 구조 4개, 객체지향 설계 1개, C++ 게임 개발 1개. 표시 수와 안내 문구 일치.
- 키보드 Enter로 필터 조작 정상.
- 테마 전환 후 새로고침 및 다른 글 이동 시 선택 유지.
- 대표 글 코드 강조 3개 및 비교 표 렌더링 확인.
- 375px, 768px, 1440px에서 홈·목록·프로젝트·대표 글의 페이지 전체 가로 넘침 없음.
- 320px에서 홈·목록은 넘침 없음. 프로젝트는 7px, 대표 글은 15px 넘침이 있으며 이전 커밋의 동일 페이지에서도 같은 값이었다. 기존 CSS를 보존했고 이 기존 문제는 이번 전환에서 수정하지 않았다.
- React 필터 페이지 콘솔 오류·경고 없음.
- 목록 전용 React JS는 합계 222,416바이트(각 파일 gzip 합계 69,622바이트)다. 기존 필터보다 실행 코드 비용은 늘었으며 홈·개별 글에는 이 번들을 로드하지 않는다. 실제 네트워크 성능 점수는 측정하지 않았다.
- 댓글 iframe과 입력 UI 로딩 확인. 대표 글은 댓글 0개였고 giscus가 아직 Discussion이 없다고 안내했다. 전환 전후 iframe의 repository/category/pathname 검색 term은 동일하다. 댓글·반응을 작성하지 않았다.

## 확인 범위의 한계와 배포 전 점검

JavaScript 없는 콘텐츠 제공은 생성 HTML에 본문·전체 카드가 포함되고 필터가 숨겨져 있음을 검사한 결과다. 브라우저의 JavaScript 차단 모드를 별도로 실행하지 않았다.

원격 push·PR·main 병합·Pages 설정 변경·공개 배포는 수행하지 않았다. GitHub Actions의 실제 Linux 실행과 운영 도메인에서의 기존 Discussion 연결은 배포 시 최종 확인해야 한다. 배포 전환과 복구 절차는 [배포 문서](06-deployment.md)를 따른다.
