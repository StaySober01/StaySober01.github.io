Unreal 반복 공간을 레벨 스트리밍으로 초기화하기

TIL · 게임 엔진 · 2026.08.25

이상현상 판별 게임 Exit 3는 같은 지하철 출구가 반복되지만 매 라운드 오브젝트 상태가 달라집니다. 상태를 하나씩 되돌리는 대신, 유지할 공간과 교체할 공간을 나누고 Gameplay Level 자체를 다시 생성하는 구조를 선택했습니다.

Exit 3의 핵심 규칙

Exit 3는 반복되는 지하철 출구를 관찰하고 이상현상의 유무를 판단하는 1인칭 게임입니다. 플레이어는 별도 선택 버튼 대신 이동 방향으로 답을 제출합니다. 정상이라고 판단하면 앞으로 진행하고, 이상현상을 발견했다면 왔던 길로 돌아갑니다. 

Stage 1: 한눈에 보이는 큰 변화
Stage 2: 주변을 살펴야 찾을 수 있는 변화
Stage 3: 정상 공간을 기억해야 찾을 수 있는 변화

라운드가 시작되면 정상과 이상 상태를 같은 확률로 정합니다. 이상 상태에서는 현재 Stage에 등록된 후보 다섯 개 중 하나만 무작위로 적용합니다. 정답이면 다음 Stage로, 오답이면 Stage 1로 돌아가며 Stage 3을 통과하면 게임을 완료합니다.

규칙은 짧지만, 오답 후 처음부터 다시 시작해도 이전 라운드의 변화가 남지 않아야 한다는 초기화 조건이 생깁니다.

반복 공간의 초기화 문제

처음에는 모든 오브젝트의 정상 상태를 저장하고 라운드가 끝날 때 복구하는 방식을 생각했습니다. 하지만 이상현상은 크기, 위치, 회전, 머티리얼, 가시성, 조명처럼 서로 다른 값을 바꿉니다. 대상이 늘어날수록 각 클래스에 저장과 복구 코드를 추가해야 하고, 한 항목만 빠져도 다음 라운드에 흔적이 남습니다.

방식장점위험
오브젝트별 상태 복구현재 레벨을 유지하며 필요한 값만 되돌릴 수 있음속성이 늘수록 초기화 누락과 클래스별 복구 코드가 증가함
Gameplay Level 재생성배치된 기본 상태에서 라운드를 다시 시작할 수 있음플레이어와 관리자처럼 유지할 대상을 별도 레벨로 분리해야 함

이 프로젝트에서는 라운드마다 공간 전체를 깨끗한 상태로 되돌리는 것이 더 중요했습니다. 그래서 개별 상태를 빠짐없이 복구하는 책임을 늘리는 대신, 변경 가능한 공간을 제거하고 다시 불러오는 방식을 선택했습니다.

Persistent와 Gameplay Level 분리

레벨을 다시 생성해도 게임 진행 정보가 사라지지 않도록 공간과 책임을 둘로 나눴습니다.

  • Persistent Level: 연결 통로, 플레이어, 판정 트리거, Stage 관리자, HUD, 레벨 스트리밍 관리자를 유지합니다.
  • Gameplay Level: 관찰 공간, 조명, 포스터, 안내판, CCTV, 소품과 이상현상 대상을 배치합니다.
연결 통로
→ Gameplay Level 진입
→ 이상현상 관찰
→ 앞 또는 뒤로 이동해 판단
→ 판정 후 연결 통로로 복귀
→ 기존 Gameplay Level 제거
→ 새 Gameplay Level 생성
→ 다음 라운드 시작

C++에서는 ULevelStreamingDynamic을 사용하는 관리 클래스를 준비했습니다. 이렇게 하면 이상현상이 바꾼 Transform, Material, Visibility를 각각 기억하지 않아도 새로 로드된 레벨의 기본 배치 상태에서 시작할 수 있습니다.

Stage 판정과 이상현상 적용

현재 Stage, 라운드 상태, 플레이어 판단은 각각 enum으로 분리했습니다. 판정은 플레이어의 판단과 라운드 상태가 같은지만 비교합니다. 

const bool bCorrect =
    (Decision == EExit3PlayerDecision::Normal &&
     State->GetRoundState() == EExit3RoundState::Normal) ||
    (Decision == EExit3PlayerDecision::Anomaly &&
     State->GetRoundState() == EExit3RoundState::Anomaly);

이상현상 Actor는 공통 기반 클래스에서 ID, 등장 Stage, 적용 여부와 ApplyAnomaly, ResetAnomaly 인터페이스를 제공합니다. 핵심 선택과 진행은 C++이 담당하고, Mesh나 Material처럼 에디터 연결이 편한 부분은 BlueprintNativeEvent로 확장할 수 있게 했습니다.

Stage Manager는 현재 Gameplay Level의 이상현상 Actor를 찾고, 현재 Stage와 일치하는 후보만 모아 하나를 적용합니다. 레벨 교체가 정상 동작하면 ResetAnomaly는 진행의 필수 조건이 아니라 개별 테스트와 재사용을 위한 안전장치가 됩니다.

첫 빌드에서 만난 문제

UENUM에는 0 기본값을 준비한다

Stage 값을 1부터 정의하자 Unreal Header Tool이 EExit3Stage does not have a 0 entry를 보고했습니다. enum은 0으로 기본 초기화될 수 있으므로 숨겨진 None = 0 UMETA(Hidden) 항목을 추가해 해결했습니다.

Editor가 사용 중인 DLL은 링크할 수 없다

소스 컴파일은 통과했지만 마지막 링크에서 LNK1104가 발생했습니다. Unreal Editor가 기존 UnrealEditor-Exit3.dll을 사용 중이어서 파일을 교체할 수 없었던 것이 원인이었습니다. Editor를 종료한 뒤 전체 빌드를 다시 실행하는 방식으로 확인해야 합니다.

새 C++ 파일 뒤에는 프로젝트 파일을 갱신한다

직접 만든 클래스가 Solution Explorer에 보이지 않았던 이유는 파일 생성 시점의 목록이 기존 프로젝트 파일에 남아 있었기 때문입니다. UnrealVersionSelector로 프로젝트 파일을 다시 생성하고 Visual Studio에서 프로젝트를 Reload해 새 파일을 반영했습니다.

첫 번째 마일스톤

현재는 C++ 폴더 구조와 GameMode, GameState, Character, ChoiceTrigger, Stage Manager, Level Stream Manager, Anomaly Actor, HUD Widget의 기반을 만든 단계입니다. 다음 작업에서는 Enhanced Input과 캐릭터 Blueprint를 연결하고 Persistent Level과 Gameplay Level을 블록아웃합니다.

첫 마일스톤은 그래픽 완성도가 아니라 다음 루프가 여러 번 안정적으로 반복되는지 확인하는 것입니다.

연결 통로
→ 관찰 공간
→ 앞 또는 뒤 선택
→ Stage 판정
→ 관찰 공간 재생성

정리

반복 공간에서 여러 오브젝트가 서로 다른 상태를 바꾼다면, 개별 복구 코드는 기능이 늘수록 누락 가능성도 함께 커집니다. Exit 3에서는 계속 유지할 진행 요소를 Persistent Level에 두고, 변할 수 있는 관찰 공간을 Gameplay Level로 분리했습니다.

이번 설계의 핵심은 레벨 스트리밍 자체보다 초기화 책임의 위치를 정한 것입니다. 먼저 게임의 판정과 반복 루프를 검증한 뒤 이상현상과 연출을 추가하면, 콘텐츠를 늘리는 동안에도 라운드의 시작 상태를 일관되게 유지할 수 있습니다.
